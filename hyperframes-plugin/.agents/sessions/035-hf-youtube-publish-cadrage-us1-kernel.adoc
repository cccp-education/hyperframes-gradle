== Mission

Reprise de hyperframes (prompt de reprise S-034 + BACKLOG) : intégrer le
**déploiement YouTube industrialisé automatique** d'une vidéo produite sur la
chaîne `@cccp.education`, avec miniature, description, timeline (chapitres),
hashtags, liens (cccp.education / talaria.school / cheroliv.com) et navigation
(vidéo suivante/précédente). Session **transverse** hyperframes + video-kernel +
capsule. Guidage pilote demandé sur la génération de la « clé API » YouTube.

== Livré

=== US-0 — Cadrage EPIC `HF-YOUTUBE-PUBLISH` (gouvernance pure)

Doc `.agents/CADRAGE_EPIC_HF_YOUTUBE_PUBLISH.adoc` :

* **Audit** 7 zones (capsule `VideoDescriptionBuilder`/`YouTubeChaptersFormatter`/
  `ViralThumbnailPlanner`, hyperframes rendu/post, `video-kernel` **sans port de
  publication**, patron secret `fish.yaml`/`FishAudioKey`).
* **Constat clé [C5]** : YouTube **upload = OAuth 2.0** (clientId/secret/refresh
  token), **pas** une clé API simple (lecture seule). Guide §2.2 (Cloud Console →
  YouTube Data API v3 → consent screen → client OAuth Desktop → Playground →
  refresh token ; piège du mode *Testing* 7 jours ; quota ≈6 uploads/jour).
* **Architecture** : N1 `video.kernel.publish` (modèle + port + validation +
  composition de description) ↔ N2 adaptateurs (`hyperframes.publish`,
  `capsule.adapter.youtube`). Frontière noyau respectée (pas de HTTP).
* **12 décisions** (D1→D12) : placement N1, port unique, **pas de SDK Google**
  (JDK `HttpClient` + Jackson), modèle neutre, validation pure, description
  partagée, résultat sealed non-jetable, secret `youtube.yaml` gitignoré,
  précédente/suivante optionnelle, miniature best-effort, tests sans réseau,
  ordre contraint par la publication du noyau.
* **6 US** (US-0→US-5) + configuration visée + 6 risques.

   compileTestKotlin` VERT ; publication Central **bundle `341922a4`**.
2. **hyperframes** re-pin `workspace-catalog/BOM 0.0.99` + toml local
   `hyperframes 0.0.8 → 0.0.9` ; `publishToMavenLocal` VERT (POM 0.0.9 importe
   `workspace-bom:0.0.99`) ; publication Central **`hyperframes-plugin 0.0.9`**
   (AUTOMATIC, propagation repo1 en cours à la clôture).

**Piège rencontré (nouveau)** : le premier upload Central a été **rejeté**
(« Dependency version information is missing for kotlin-stdlib-jdk8 /
jackson-databind / jackson-module-kotlin ») parce que le POM importait
`workspace-bom:0.0.99` **pas encore propagé** sur repo1. Correctif : publier
MEMPHIS d'abord, attendre `repo1 …/0.0.99.pom` **HTTP 200**, puis republier
hyperframes → succès. Leçon : dans un DAG N0→N2, la **propagation repo1** de
l'amont est un prérequis *de fait* de la publication aval (le POM est validé par
Central contre les artefacts déjà indexés).

== Décisions / points d'attention

* Le pilote parle de « clé API » : **corrigé** dans la configuration — il faut un
  **jeu d'identifiants OAuth 2.0** (clientId/clientSecret/refreshToken). La clé
  API simple reste optionnelle (lecture pour résoudre précédente/suivante).
* Les tests **ne publient jamais réellement** (fake `VideoPublisher` en unit/BDD ;
  dogfooding réel = gardé).
* Ordre cross-borough : **noyau d'abord** (US-1 → publication → US-2 hyperframes →
  US-3 capsule), conforme à la discipline DAG N1→N2.
