== Mission

US-2 de l'EPIC `HF-KERNEL-ADAPTER` : aligner le contrat N3 (`composite-context.json`
/ `metadata.json`) sur le **modèle neutre** du noyau — exposer `engine`, des
`segments`, et une durée **mesurée** (D3 du cadrage). Méthode baby-step DDD/TDD/BDD.
**Local = Build, Tests = CI**.

== Constat

- `durationSeconds` **mesuré** : déjà livré par **D-C** (S-017, sonde ffprobe).
- Le contrat N3 n'exposait **ni** l'identité du moteur producteur (`engine`) **ni**
  de vue `segments` du noyau.
- Le consommateur N3 (`runner-gradle`) **ne parse pas** ce contrat (`grep` = 0) →
  enrichissement **additif** sans risque de split-brain cross-borough.

== Livrable

=== Contrat — `HyperframesParseContext`

- Nouveau champ **`engine: String = "hyperframes"`** (identité neutre, alignée sur
  `VideoEngine.name()`), via `HyperframesParseContext.ENGINE` (source unique).
- Nouveau champ **`segments: List<HyperframesSegment> = emptyList()`** : vue
  **modèle neutre** du document — une entrée par **borne de composition**
  (`data-composition-id`). Un moteur document-entier n'a ni narration ni scène ;
  les compositions sont ses unités adressables (D6 du cadrage).
- Nouveau DTO `HyperframesSegment(index, id)`.
- Tous les nouveaux champs sont **additifs avec défauts** → backward-compat JSON totale.

=== Extracteur — `HyperframesContextExtractor`

- Mappe les compositions détectées en `segments` ordonnés (`index`, `id`).
