== Dogfooding CLI réel (US-5)

Environnement : Node v22 / npm 11 ; paquet npm **`hyperframes@0.8.155`** installé ;
`hyperframes doctor` ✓ (Chrome, ffmpeg/ffprobe, GPU). Consommateur transitoire
`/tmp/opencode/hf-dogfood` (Règle 2), plugin publié en local (`publishToMavenLocal`).

**Résultat** : `hyperframesPipeline` (generate → render → collect) avec la **vraie
CLI** produit un **vrai MP4** (`dogfood.mp4`, 21 604 octets, 1,0 s, encodage GPU) et un
`composite-context.json` complet (`engine=hyperframes`, `durationSeconds=1.0`,
`version=0.0.3`, `segments`).

**2 bugs révélés et corrigés** :
1. **Bridge CLI faux** — la vraie CLI est `hyperframes render [DIR] -o <out>` ; la
   commande du plugin passait `--input <html>` (option **inexistante** →
   échec). Corrigé : `render <projectDir> --output <mp4>` (`HyperFramesEngine`).
   Les stubs CLI des tests ignorent l'argument positionnel → suites inchangées.
2. **`version: "unspecified"` dans le N3** — le plugin rapportait `target.version`
   (version du projet **consommateur**). Corrigé : version du plugin lue depuis le
   manifeste du jar (`Implementation-Version`, posé par `tasks.jar`) via
   `HyperframesVersion.value` → `version=0.0.3`.
