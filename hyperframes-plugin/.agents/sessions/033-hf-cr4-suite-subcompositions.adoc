== Contexte

Suite directe de HF-CR4 (S-031). Le rendu était conforme (0 erreur lint) mais
`hyperframes check` laissait **7 warnings** `nested_structure_needs_subcomposition`
(chaque scène `class="scene clip"` est un élément timeline contenant des `<div>`
imbriqués — les scènes devraient être des **sous-compositions**) + 1 warning
`timeline_track_too_dense` (6 clips sur la même piste).

== Correctif — scènes en sous-compositions

Lecture de la règle CLI (`hasNestedStructure` / `isSubCompositionHost`) : tout
élément portant `data-composition-id` est **exempté**. Chaque scène devient donc
une **sous-composition** :

* `data-composition-id="<id>"` sur la scène (exempte du warning imbriqué) ;
* **une piste par scène** (`data-track-index="<index>"`) → zéro
  `timeline_track_too_dense` ;
* chaque scène possède sa propre timeline `window.__timelines["<id>"]` (réutilise
  celle du template/auteur, ou la crée), **ré-enregistrée** puis `seek(0)` ; le
  runtime auto-neste la sous-composition ;
* la racine `#stage` (`data-composition-id="root"`) enregistre une timeline pausée.

**Bug attrapé par le dogfooding** : la première implémentation créait la timeline
des scènes sans la **ré-enregistrer** (`var t = window.__timelines[id] || …` mais
aucun `window.__timelines[id] = t`). Le producteur sondait alors 45 s ces
compositions (setup de rendu **47 s**) et rendait les scènes **blanches**.
Corrigé (ré-enregistrement) → setup **2,3 s**, toutes les scènes rendues.
