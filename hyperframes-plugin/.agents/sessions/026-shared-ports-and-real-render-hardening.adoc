== A — Consommation réelle des ports partagés (2ᵉ consommateur)

Le noyau `video-kernel 0.4.0` expose `TextToSpeech`, `AudioPostProduction`
(+ `AudioPostSettings`), `SubtitleBurnIn` (fun-interfaces pures, jamais d'exception).
hyperframes les consomme via un nouveau domaine `hyperframes.post` :

[cols="1,3", options="header"]
|===
| Artefact | Rôle
| `CommandRunner` (+ `ProcessBuilderCommandRunner`) | seam process test-injectable
| `HyperframesSubtitleCommand` / `HyperframesAudioPostCommand` / `HyperframesTtsCommand` | builders purs
| `FfmpegSubtitleBurnIn` / `FfmpegAudioPostProduction` | impls N2 des ports (dégradation `false`)
| `EspeakTextToSpeech` | impl N2 du port TTS
| `NarrationTrackExtractor` | extraction pure de la narration du HTML enrichi
|===

Tâches :

* **`postProcessHyperframes`** — burn-in (si `subtitleFile`) puis audio post (si
  `audioPostEnabled`) sur le MP4 rendu ; dégradation **pass-through** (toujours
  écrit `<name>.mp4` dans `build/hyperframes/post`).
* **`generateHyperframesNarration`** — narration des `[hyperframes-track]` →
  `narration-<n>.wav` (skip économie d'encre, dégradation non fatale).

Extension : `subtitleFile`, `audioPostEnabled`, `bgmFile`, `bgmLevelDb`
(-18.0), `loudnessTargetLufs` (-16.0), `duckingEnabled`, `ffmpegExecutable`,
`ttsExecutable`, `ttsVoice` (conventions rétro-compatibles).

Pin : `gradle/libs.versions.toml` `video-kernel 0.3.0 → 0.4.0`.

== Correctifs post-CI (runs `38791275997`, `38792202056`)

La 1re CI `Test` (`38791275997`) a révélé **2 échecs unit/BDD**, même cause racine :
le **faux `CommandRunner`** des tests écrivait dans `argv.last()` (supposant la
sortie en dernier) — vrai pour subtitle/audio-post, **faux** pour TTS dont le
dernier argument est le **texte** (sortie après `-w`). Correctif **test-only**
(résolution par `-w`, fallback `last`).

La 2e CI (`38792202056`) a révélé **3 échecs functional** — un **bug réel** de
contrat Gradle : `HyperframesExtension.outputDir` portait `@OutputDirectory`
(anti-pattern historique S-017/D-A). La consommer comme **entrée** d'une nouvelle
tâche fait échouer Gradle : « property … declared as an output property of
extension … but does not have a task associated with it ». **Correctif
architectural** : les annotations d'entrée/sortie de tâche appartiennent aux
**tâches**, pas à l'extension → `@OutputDirectory` retiré de l'extension
(l'intention reste en KDoc) ; garde `HyperframesExtensionContractTest` mise à jour
(assertion : `outputDir` n'est ni `@InputDirectory` ni `@OutputDirectory`). Un
test fonctionnel adapté (le répertoire de rendu doit exister pour la validation
d'entrée de Gradle). Diagnostic établi depuis un consommateur jetable local
(build, pas de suite de tests), puis re-push.
