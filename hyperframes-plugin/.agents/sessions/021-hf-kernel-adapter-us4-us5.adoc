== US-4 — périmètre réel (cadrage)

Le noyau `video-kernel` est un **contrat pur** (modèle + ports), sans dépendance
Gradle ni moteur (garde `video.ci.KernelBoundaryTest`). Les capacités **TTS,
sous-titres et audio** sont des **N2** (moteurs concrets) — les faire porter par le
noyau violerait la doctrine (« N0/N1 = contrats purs ») et le précédent LLM-RESILIENCE
N0 CADUQUE (S-162). **Décision** : ces facettes sont **HORS SCOPE du noyau** ; elles
restent des capacités de capsule (N2) et ne peuvent être « consommées » par
hyperframes que via un EPIC N2→N2 interdit par le DAG.

**Facettes réellement noyau-compatibles** — livrées ici :
- **durée** : l'adapter `HyperFramesEngine` remplit désormais
  `VideoOutcome.durationSeconds` via une sonde **injectable** (`HyperFramesEngineConfig.durationProbe`)
  → parité avec l'adapter reveal de capsule (un orchestrateur générique lit une
  `VideoOutcome` **complète**, quelle que soit la source).
- **config** : `ffprobeExecutable` câblé à la tâche de rendu (comme la collecte) ;
  dégradation `0.0` si `ffprobe` absent (jamais d'échec).

== US-5 — BDD e2e
