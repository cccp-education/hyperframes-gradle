== Résumé

Clôture EPIC HF-4 : la task `collectHyperframesRetrieve` produit désormais un
`composite-context.json` **typé** conforme au contrat N3 documenté
(`HYPERFRAMES_ARCHITECTURE.adoc:304-327`). Un contrat DDD value object
`HyperframesParseContext` est la source unique de vérité, un domain service
`HyperframesContextExtractor` extrait les `data-*` du HTML enrichi, et la
sortie JSON est consommable par runner-gradle sans parsing HTML.

Méthode : baby-step DDD/TDD/BDD — unit → fonctionnel → Cucumber.

== Ce qui a été fait

=== DDD — contrat typé N0 (valeur produit)
- `contract/HyperframesParseContext.kt` — value object racine
  - `HyperframesParseContext` (plugin, version, output, source, renderedAt, renderDurationMs)
  - `HyperframesVideoOutput` (video, path, sizeBytes, durationSeconds, width, height, fps, codec)
  - `HyperframesAsciidocSource` (asciidoc, compositions, tracks)
- `contract/HyperframesContextExtractor.kt` — domain service pur
  - parse `<div id="stage">` data-width/height/fps
  - collecte `data-composition-id` (distinct)
  - compte `data-track-index` (distinct)
  - lit la taille MP4 depuis le filesystem

=== TDD — unit tests (14)
- `HyperframesParseContextTest` (5) — pins JSON shape, round-trip Jackson
- `HyperframesContextExtractorTest` (9) — stage dimensions, compositions,
  tracks count, MP4 size, missing file, codec default, asciidoc name

=== Implémentation — task rewiring
- `CollectHyperframesRetrieveTask.kt` réécrite :
  - lit MP4 + index.html dans `outputDir`
  - appelle `HyperframesContextExtractor`
  - sérialise `HyperframesParseContext` en JSON
  - si MP4/HTML manquants → succès sans écriture (idempotent)
  - `pluginVersion` Property injecté depuis `project.version`
- `HyperframesPlugin.kt` — câblage `task.pluginVersion.set(target.version.toString())`

=== BDD — Cucumber (4 scénarios)

  2. Video descriptor (video, width, height, fps, sizeBytes, codec=h264)
  3. Source descriptor (asciidoc, compositions, tracks)
  4. No-artifacts case (task succeeds, no file written)
