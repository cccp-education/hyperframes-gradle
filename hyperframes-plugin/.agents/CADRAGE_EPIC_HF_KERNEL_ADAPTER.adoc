== Objectif

Préparer `hyperframes-gradle` à devenir le **2ᵉ adaptateur** du **noyau vidéo partagé**
(`video-kernel`) en cours d'extraction côté capsule (EPIC `CAP-ENGINE-DECOUPLING`).

But : disposer d'une **littérature agentique prête** (ports à implémenter, gaps à
combler, défauts à corriger, contrat N3 à aligner) afin que le **câblage à l'extraction
soit anticipé** — sans implémenter tant que le noyau capsule n'est pas posé.

_Origine_ : session pilote 2026-10-12 — « préparer la littérature agentique de
gouvernance de hyperframes pour qu'il soit prêt quand on aura proprement préparé
l'extraction, pour un câblage plus anticipé ».

== Constats (audit au code S-184)

=== C1 — État réel

16 fichiers prod / 3 tâches. Pipeline : AsciiDoc → AsciidoctorJ → HTML enrichi
(stage, data-*, GSAP) → CLI Node → MP4. **Aucun `dependsOn`** entre les 3 tâches
(ordre par convention de fichier partagé).

=== C2 — Défauts de contrat vérifiés

[cols="1,3", options="header"]
|===
| # | Défaut
| D-A | `HyperframesExtension.outputDir` annoté `@InputDirectory` (devrait être output).
| D-B | `node-gradle` **déclaré en dépendance mais jamais utilisé** (résolution FS + `which node`).
| D-C | `HyperframesContextExtractor`: `durationSeconds` **codé en dur `0.0`** → pas de ffprobe, pas de validation durée.
| D-D | Commande exécutée `node <script> render` vs description `npx hyperframes render` — incohérence doc/code.
| D-E | `pronunciation domain` **perdu** dans le contrat N3 (toujours `null`).
| D-F | Aucun cache/incremental (toutes tâches `@DisableCachingByDefault`) ; pas de source set `functionalTest` ; pas de NoOp/strict.
|===

=== C3 — Ce que hyperframes a en propre (et que le noyau ne fournit pas)

Le **runtime HyperFrames** (motion HTML continue seek-safe, GSAP), **4 templates**
motion purs (`title-card`, `code-diff`, `data-chart`, `kinetic-captions`), le
**bridge CLI Node**, et le noyau **prononciation**. C'est **le moteur de rendu visuel**
que capsule n'a pas (capsule = slides). C'est exactement le rôle du 2ᵉ `VideoEngine`.

=== C4 — Gap vs noyau capsule

Absent chez hyperframes, présent (récupérable) chez capsule : TTS, audio-post,
sous-titres/burn-in, validation durée, QC, chapitres, podcast, transcript,
multi-langue, LLM (koog), config 4-source, viral, contexte augmenté.

== Décisions

. **D1 — hyperframes = 2ᵉ `VideoEngine` adapter**, pas une réécriture. Le parser
   AsciiDoc→HTML + le bridge CLI = l'adapter ; le reste (TTS, sous-titres, audio, durée,
   config) vient du **noyau partagé**.
. **D2 — Corriger les défauts d'abord** (US-1) avant tout câblage du noyau.
. **D3 — Aligner le contrat N3** sur le modèle neutre (US-2) : `metadata.json` /
   `composite-context.json` exposent `segments`, `durationSeconds` **mesuré**, `engine`.
. **D4 — Implémenter le port `VideoEngine`** (US-3) : `HyperframesCliEngine.render(...)`.
. **D5 — Consommer le noyau partagé** (US-4) : TTS/sous-titres/audio/durée/config.
. **D6 — Vocabulaire** : hyperframes garde son domaine (`composition`, `track`) mais
   **expose** des `VideoSegment` au noyau (frontière via les ports).
. **D7 — DAG** : hyperframes reste **N2** ; le noyau est **N1** (ports possiblement N0).
   Pas de cycle (le noyau ne dépend pas de hyperframes).

== Mise à jour S-021 — périmètre de US-4 (durée/config ; TTS/audio/sous-titres hors noyau)

_Statut EPIC (S-021)_ : US-0 ✅ S-015 · US-1 ✅ S-017 · US-2 ✅ S-019 · US-3 ✅ S-018 ·
US-4 **partiel** (périmètre noyau) · US-5 ✅ S-021. Le noyau est gelé + publié
`video-kernel:0.2.0` (package neutre `video.kernel.*`, S-194).

**Décision S-021** — le noyau `video-kernel` est un **contrat pur** (modèle + ports,
garde `video.ci.KernelBoundaryTest`), sans dépendance Gradle ni moteur. Les facettes
**TTS / sous-titres / audio** sont des **N2** (moteurs concrets) : les porter dans le
noyau violerait la doctrine « N0/N1 = contrats purs » et le précédent LLM-RESILIENCE N0
CADUQUE (S-162). Elles sont donc **HORS SCOPE du noyau** — hyperframes ne peut les
consommer que via un EPIC N2→N2 (interdit par le DAG).

**Facettes noyau-compatibles livrées (US-4, S-021)** :
- **durée** — `HyperFramesEngineConfig.durationProbe` (sonde injectable) → l'adapter
  remplit `VideoOutcome.durationSeconds` (parité avec l'adapter reveal de capsule) ;
- **config** — `ffprobeExecutable` câblé à la tâche de rendu ; dégradation `0.0`.

**US-5 (S-021)** — BDD e2e via `hyperframesPipeline` (generate → render → collect),
CLI + sonde stubbées ; `hf_pipeline_e2e.feature`. Dogfooding réel (CLI npm) conditionné
à l'environnement/accord.

_Reste_ : dette D-F (cache/incremental profond + source set `functionalTest`).
