== EPIC HF-7 — Pronunciation Control (TTS Phonetic Hints)

_Vision_ : Une mauvaise prononciation TTS (« dos » lu « dosse » au lieu de « do »)
détruit la crédibilité d'un contenu de formation. L'auteur AsciiDoc doit
pouvoir corriger la phonétique sans toucher au code Node.js. Le plugin Kotlin
extrait les hints de l'AsciiDoc et les injecte dans le HTML HyperFrames sous
forme de JSON island consommé par la CLI au rendu.

[cols="1,3,2", options="header"]
|===
| Phase | Livrable | Statut
| HF-7a | Value object `PronunciationHint` (word, phonetic, language) + tests unit | ✅ Session 010
| HF-7b | `PronunciationDictionary` aggregate (add, render JSON island, merge domain, find) + Cucumber EN | ✅ Session 010
| HF-7c | DSL AsciiDoc `[hyperframes-pronunciation, lang="fr"]` + processor `expandPronunciationBlocks` + tests fonctionnels | ✅ Session 010
| HF-7d | Dictionnaire de domaine pré-câblé (video-fr, video-en, custom) + tests unit — recentré S011 (fuite bounded context corrigée : fpa-fr → video-fr) | ✅ Session 010
| HF-7e | Hints inline `<<mot|phonétique>>` dans narration + processor `expandInlineHints` + Cucumber EN | ✅ Session 010
| HF-7f | Intégration `metadata.json` N3 (section pronunciation pour traçabilité) + tests unit | ✅ Session 010
| HF-7g | Tests d'intégration end-to-end (scénarios Cucumber complets) | ✅ Session 010
|===

_Pattern DDD/TDD/BDD_ : value object pur → aggregate → processor regex →
tests unit (Red) → implémentation (Green) → Cucumber EN (critères acceptation).
Le dictionnaire reste côté auteur (AsciiDoc), pas côté moteur (Node.js).
