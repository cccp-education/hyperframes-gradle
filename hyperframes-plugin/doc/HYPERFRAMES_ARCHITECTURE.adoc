== Vision

Transformer automatiquement un document AsciiDoc annoté en vidéo MP4
via le moteur HyperFrames (HeyGen, Apache 2.0, 22.7k ⭐), sans passer
par reveal.js. Le DSL de configuration est porté par AsciidoctorJ.
Le bridge Node.js est isolé derrière ProcessBuilder.

=== Stack

[cols="3,5"]
|===
| Brique | Rôle
| AsciidoctorJ | Parse l'AsciiDoc source, extrait les blocs customs et les docinfo attributes
| codex-gradle | Dépendance compileOnly — partage AsciidoctorJ
| HyperFrames CLI | Moteur de rendu HTML → MP4 (Puppeteer + FFmpeg, Node.js)
| gradle-node-plugin | Gère l'installation de Node.js et du package npm hyperframes (pinné, reproductible)
| ProcessBuilder | Bridge JVM → CLI géré par le plugin Gradle Node (pas de couplage code)
|===

'''

== Bridge Node.js — ProcessBuilder

Le bridge entre la JVM (Gradle/Kotlin) et le CLI HyperFrames (Node.js/TypeScript)
est géré par le plugin `com.github.node-gradle:gradle-node-plugin` (même pattern
que slider-gradle). Node.js est pinné, downloadé automatiquement par Gradle.

=== Stratégie

Le plugin n'importe JAMAIS de code Node.js directement. Le contrat est :
- Le plugin Gradle Node gère l'installation de Node.js et du package npm `hyperframes`
- `ProcessBuilder` exécute le binaire `node` fourni par le plugin
- Communication par fichiers sur disque :

[source,kotlin]
----
class RenderHyperframesTask : DefaultTask() {

    @TaskAction
    fun render() {
        val inputFile = extension.inputDir.resolve("index.html")
        val outputFile = extension.outputDir.resolve("${extension.outputName}.mp4")

        // Le chemin node est résolu via le plugin Gradle Node
        val nodeExec = project.extensions.getByType(NodeExtension::class.java)
            .nodeBinDir
            .get()
            .resolve("node")

        val process = ProcessBuilder(
            nodeExec.absolutePath,
            hyperframesCliScript.absolutePath,
            "render",
            "--input", inputFile.absolutePath,
            "--output", outputFile.absolutePath
        )
            .directory(extension.inputDir)
            .inheritIO()
            .start()

        val exitCode = process.waitFor()
        require(exitCode == 0) {
            "HyperFrames render failed with exit code $exitCode"
        }

        require(outputFile.exists() && outputFile.length() > 0) {
            "HyperFrames output file is empty or missing: ${outputFile.absolutePath}"
        }
    }
}
----

=== Gestion d'erreurs

- Node.js pas encore download → le plugin Gradle Node le télécharge automatiquement à la config. Si download échoue, message clair : "gradle-node-plugin: Node.js download failed. Check network / proxy settings"
- Package npm hyperframes pas installé → le plugin Gradle Node installe via `npm install` en tâche Gradle. Si échec, message : "npm package hyperframes installation failed. Check package name / version"
- Timeout → configurable via extension (`renderTimeoutMs`, défaut 300 secondes)
- Crash → exception Gradle avec le stderr capturé

== Décisions Techniques

[cols="2,5,3", options="header"]
|===
| Décision | Raison | Alternative rejetée
| AsciidoctorJ en implementation (HF-1) | Nécessaire pour GradleTestKit ; passera en compileOnly en HF-4 | compileOnly (cassait les tests)
| gradle-node-plugin + ProcessBuilder | Node.js pinné, download auto Gradle, CI reproductible | npx système (version non garantie), J2V8 (trop lourd), GraalJS (trop lourd)
| HyperFrames CLI externe | Isolation, upgrade indépendant | Bundler HyperFrames dans le plugin (trop complexe)
| MP4 h264 + AAC | Standard universel, compatible tous lecteurs | WebM (Playwright natif, moins compatible)
| DSL en AsciiDoc customs | Naturel pour l'écosystème existant | DSL YAML/JSON (moins intégré)
|===

== Risques et Mitigations

[cols="1,3,3", options="header"]
|===
| Risque | Impact | Mitigation
| HyperFrames CLI API instable (v0.6.x) | Cassure du pipeline | Pin de version, tests golden file MP4
| Download Node.js échoue sur CI (proxy, réseau) | Bloquant | Plugin Gradle Node gère le download auto ; fallback = image Docker avec Node.js préinstallé
| Headless Chrome lent sur CI | Timeout | Timeout configurable, cache des frames
| AsciidoctorJ version mismatch | Compilation | compileOnly = version du consommateur, pas du producteur
|===
