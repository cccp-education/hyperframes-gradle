*Priorité* : P1
*EPIC* : HF-7
*Statut* : ✅ TERMINÉ (session 010) — 7 phases HF-7a→g livrées

. Valeur
Une mauvaise prononciation détruit la crédibilité d'un contenu de formation.
Exemple concret : le mot « dos » prononcé « dosse » au lieu de « do ».

la crédibilité tombe à zéro dès la première seconde.

L'auteur AsciiDoc doit pouvoir corriger la phonétique sans toucher au
code Node.js ni au moteur TTS. Le plugin Kotlin extrait les hints de
prononciation de l'AsciiDoc source et les injecte dans le HTML HyperFrames
pour que la CLI consomme le dictionnaire au rendu.

. Critères d'acceptation
- Un bloc `[hyperframes-pronunciation]` au niveau document définit un
  dictionnaire mot → phonétique approchée
- Le dictionnaire est injecté dans le HTML HyperFrames sous forme de
  `<script type="application/json" id="hf-pronunciation">...</script>`
- Le `metadata.json` N3 embarque le dictionnaire pour traçabilité
- Un dictionnaire de domaine pré-câblé couvre le vocabulaire formation
  (référentiel, Docker, Kubernetes, etc.)
- Les hints inline dans le texte de narration permettent une correction
  ponctuelle sans dictionnaire global

== EPIC HF-7 — Pronunciation Control (TTS Phonetic Hints)

_Vision_ : Donner à l'auteur AsciiDoc le pouvoir de corriger la phonétique
TTS sans toucher au code Node.js. Une mauvaise prononciation est rédhibitoire
pour la crédibilité d'un contenu de formation professionnel.

_Problème constaté_ : Le moteur TTS lit « dos » comme « dosse » au lieu de « do ».
Ce défaut détruit la crédibilité du formateur dès la première seconde.

_Architecture_ : Le plugin Kotlin extrait les hints de prononciation de
l'AsciiDoc source et les injecte dans le HTML HyperFrames sous forme de
JSON island. La CLI HyperFrames consomme ce dictionnaire au rendu.
Le contrôle reste côté auteur (AsciiDoc), pas côté moteur (Node.js).

=== HF-7a — Value Object `PronunciationHint`

*Priorité* : P1
*Méthode* : TDD baby-step — tests unit d'abord, implémentation après
*Statut* : ✅ TERMINÉ (session 010)

DDD value object pur représentant une entrée du dictionnaire de prononciation.

. Propriétés
- `word: String` — le mot à corriger (ex: "dos", case-insensitive)
- `phonetic: String` — la phonétique approchée (ex: "do")
- `language: String?` — langue optionnelle (ex: "fr", "en") pour désambiguïsation

. Tests unit (Red → Green)
- `PronunciationHint` rend un objet JSON valide `{"word":"dos","phonetic":"do"}`
- `PronunciationHint` avec langue ajoute `"language":"fr"`
- `PronunciationHint` rejette un mot vide → exception
- `PronunciationHint` rejette une phonétique vide → exception
- `PronunciationHint` est case-insensitive sur `word` (normalisation lower)

=== HF-7b — `PronunciationDictionary` aggregate (dictionnaire de domaine)

*Priorité* : P1
*Méthode* : TDD baby-step — tests unit + Cucumber EN

Aggregate root qui collecte les hints et produit le JSON injecté dans le HTML.

. Propriétés
- `hints: List<PronunciationHint>` — les entrées du dictionnaire
- `language: String?` — langue par défaut du dictionnaire

. Comportements
- `add(hint)` — ajoute un hint (déduplication sur word+language)
- `render(): String` — produit le JSON island complet
  `<script type="application/json" id="hf-pronunciation">[...]</script>`
- `merge(domain: PronunciationDictionary)` — fusionne avec un dictionnaire
  de domaine pré-câblé (les hints de l'auteur écrasent ceux du domaine)
- `find(word: String): PronunciationHint?` — lookup case-insensitive

. Tests Cucumber (Gherkin EN)
- Scenario: dictionary renders a single hint as JSON island
- Scenario: dictionary deduplicates hints on word+language
- Scenario: author hints override domain dictionary entries
- Scenario: empty dictionary renders empty JSON array

=== HF-7c — DSL AsciiDoc `[hyperframes-pronunciation]`

*Priorité* : P1
*Méthode* : TDD baby-step — tests fonctionnels (processor end-to-end)

Bloc AsciiDoc au niveau document pour déclarer le dictionnaire global.

. Syntaxe AsciiDoc

```
----

```

- AsciiDoc sans bloc pronunciation → HTML sans JSON island
- AsciiDoc avec hint inline dans narration → hint extrait et injecté
- AsciiDoc avec mot mal écrit → exception claire (format attendu : `mot: phon`)

=== HF-7d — Dictionnaire de domaine pré-câblé (vocabulaire vidéo générique)

*Priorité* : P2
*Méthode* : TDD baby-step — tests unit
*Statut* : ✅ TERMINÉ (session 010) — recentré session 011 (fuite bounded context corrigée)

Dictionnaire par défaut couvrant le vocabulaire générique de la production vidéo,
activable via extension Gradle `pronunciationDomain.set("video-fr")`.

. Domaines pré-câblés
- `video-fr` — vocabulaire vidéo francophone (narration, transition, fondu, rendu)
- `video-en` — vocabulaire vidéo anglophone (render, codec, keyframe, overlay)
- `custom` — dictionnaire utilisateur fourni via fichier `.json`

[NOTE]
====
Le plugin est un artefact OSS générique (AsciiDoc → vidéo). Les dictionnaires
embarqués couvrent uniquement le vocabulaire de la production vidéo. Un borough
consommateur avec un vocabulaire métier privé (formation réglementaire, médecine, juridique...)
injecte son propre dictionnaire via configuration Gradle, sans l'embarquer dans le
plugin public.
====

. Implémentation
- Ressources classpath `domain/video-fr.json`, `domain/video-en.json`
- Chargement lazy via `PronunciationDictionary.loadDomain(name)`
- Fusion : auteur > domaine > vide (priorité décroissante)

. Tests unit
- `loadDomain("video-fr")` retourne un dictionnaire non vide
- `loadDomain("inconnu")` → exception claire
- Fusion auteur + domaine : hint auteur écrase hint domaine
- `loadDomain("custom")` lit un fichier JSON fourni
